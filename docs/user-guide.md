# proxystack-web 使用手册

proxystack-web 用于在一台 Linux 服务器上集中管理 xray 与 mihomo 代理服务，并为代理用户提供订阅。系统由两个服务组成：

- **管理端**：提供 Web 管理面板，负责录入用户与 stack、生成并下发代理配置、启停代理服务、管理依赖版本、监控流量、执行定时任务和签发订阅包。
- **订阅端**：向代理客户端提供订阅内容。订阅端的数据全部来自管理端签发的订阅包，可以由管理端通过 SSH 正向转发在线发布，也可以在网络互不连通时人工拷贝。

本手册按安装、首次使用、日常操作、账号安全、升级、备份迁移、救援和卸载的顺序说明。

## 1. 系统要求

- Linux，使用 systemd 226 及以上版本作为 init 系统。经过完整验证的发行版为 Debian 12 和 Ubuntu 24.04。
- CPU 架构为 amd64 或 arm64。
- 安装时需要 root 权限。管理端依赖 polkit，系统未安装时安装脚本通过 apt、dnf 或 yum 自动安装。
- 管理端下载 xray、mihomo 和 geo 数据需要访问 GitHub。服务器无法直连时，可以在面板中配置下载代理（见第 7.2 节）。

## 2. 安装

安装脚本按角色安装：

| 角色 | 安装内容 |
| --- | --- |
| `panel`（默认） | 管理端：服务账号 `proxystack-web`、目录 `/opt/proxystack-web`、systemd unit 与 polkit 规则，初始化数据库并启动服务 |
| `sub` | 订阅端：服务账号 `proxystack-web-sub`、目录 `/opt/proxystack-web-sub` 与 systemd unit |
| `all` | 管理端与订阅端安装在同一台机器上，订阅端自动信任本机管理端的签名公钥 |

### 2.1 安装管理端

```bash
curl -fsSL https://raw.githubusercontent.com/sunliang711/proxystack-web/refs/heads/main/deploy/install.sh | sudo bash
```

服务器访问 GitHub 需要代理时，先设置环境变量，使安装脚本内部的下载同样经过代理：

```bash
export https_proxy=http://127.0.0.1:7890
curl -fsSL --proxy "$https_proxy" https://raw.githubusercontent.com/sunliang711/proxystack-web/refs/heads/main/deploy/install.sh | sudo -E bash
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--role panel\|sub\|all` | 安装角色，默认 `panel` |
| `--version vA.B.C` | 安装指定版本，默认最新版本 |
| `--listen ADDR`、`--port PORT` | 管理端监听地址与端口，默认 `0.0.0.0:9443` |
| `--restore FILE` | 用迁移包初始化管理端，不生成新的管理员密码（见第 8.2 节） |
| `--binary FILE` | 安装本地的二进制文件，不从网络下载 |

安装完成后，终端打印面板地址、用户名和初始密码：

```text
proxystack-web initialized.
  Panel URL:  http://203.0.113.10:9443/
  Username:   admin
  Password:   ********************
```

初始密码只打印这一次，数据库只保存其哈希值。面板挂载在根路径下，在浏览器中打开 `http://<服务器地址>:9443/` 即可进入登录页。面板直接暴露在公网时，建议用 nginx 加 TLS，或只对可信来源开放该端口。

安装脚本只负责首次安装。目标机器上已经存在管理端数据库时，脚本在执行任何改动之前退出，正在运行的服务和已有数据不受影响。管理端的升级在面板中完成（见第 7.1 节）。

### 2.2 安装订阅端

订阅端单独部署时，先在管理端的「发布订阅包」页面复制来源名和签名公钥，然后在订阅端机器上执行：

```bash
curl -fsSL https://raw.githubusercontent.com/sunliang711/proxystack-web/refs/heads/main/deploy/install.sh \
  | sudo bash -s -- --role sub --source main --public-key 'ed25519:...'
```

订阅端默认监听 `127.0.0.1:9444`，可以用 `--sub-listen` 和 `--sub-port` 指定。安装脚本只是 `sub deploy apply` 的薄封装；再次执行时会保留配置和已导入的订阅包，替换二进制、重启服务并做版本健康检查，失败自动恢复上一版。

脚本地址中的 `main` 只决定安装脚本的版本；未指定 `--binary` 时，脚本下载 GitHub Release 的二进制，默认使用最新正式发布版本，不会从 `main` 源码编译。旧版二进制的 CLI 默认目录仍可能是 `/opt/proxystack-sub`，管理订阅数据时请显式指定 `sub --dir /opt/proxystack-web-sub`，以便与服务读取的目录保持一致。

本项目使用 `/opt/proxystack-web-sub`、账号 `proxystack-web-sub` 和 `proxystack-web-sub.service`，与 proxystack-go 的 pssub（`/opt/proxystack-sub`、`proxystack-sub.service`）独立，可以同时安装。管理订阅服务使用：

```bash
sudo systemctl status proxystack-web-sub.service
sudo systemctl restart proxystack-web-sub.service
sudo journalctl -u proxystack-web-sub.service
```

安装和卸载会检查服务实际执行的命令、配置和安装标记，遇到归属不明的目录或同名服务时退出。普通卸载保留 `.proxystack-web-sub` 标记，便于之后重装或执行 `--purge`；不要手工复制该标记到其他项目目录。

离线使用裸二进制时也调用同一部署命令：

```bash
sudo ./proxystack-web-linux-amd64 sub --dir /opt/proxystack-web-sub deploy apply \
  --sha256 '<发布页校验值>' --source main --public-key 'ed25519:...'
sudo /opt/proxystack-web-sub/bin/proxystack-web sub --dir /opt/proxystack-web-sub deploy rollback
sudo /opt/proxystack-web-sub/bin/proxystack-web sub --dir /opt/proxystack-web-sub deploy uninstall
```

普通卸载保留配置和订阅数据；追加 `--purge` 才删除整个目录和服务账号。新版不再支持 `--migrate-sub`，旧目录安装应先用支持迁移的旧版本完成迁移，再升级到新版。

### 2.3 配置 nginx 反向代理

管理端和订阅端都只提供明文 HTTP，TLS 应由 nginx 终结。反向代理管理端时需要满足以下要求：

- 传递 `X-Forwarded-For`，取值为 `$remote_addr`；传递 `X-Forwarded-Proto`，取值为 `$scheme`。管理端以经 HTTPS 访问作为会话 cookie 携带 Secure 属性的依据，并以此记录审计日志和登录限速使用的来源地址。
- 关闭响应缓冲（`proxy_buffering off`），并把读超时设为一小时左右。运行状态、作业进度和日志通过服务器推送事件实时传输。
- 取消请求体大小限制（`client_max_body_size 0`），以便上传迁移包和依赖安装包。

管理端只采信本机回环地址连入时携带的 `X-Forwarded-For`，并取其中最后一个地址。nginx 部署在其他机器上时，审计日志记录的是 nginx 的地址，登录限速也按该地址计算。

## 3. 首次登录

1. 用安装时打印的地址、用户名和初始密码登录。
2. 首次登录后必须先设置新密码，新密码至少 10 个字符。改密完成前，面板的其他功能不可用。
3. 建议随后在「账号安全」页面开启两步验证（见第 6 节）。
4. 「总览」页面顶部的初始化清单按顺序列出首次使用需要完成的步骤：设置对外地址、安装 xray 和 mihomo、创建第一个用户、创建第一个 Stack、应用配置，以及按需发布订阅包。每一步根据面板中的实际数据判定是否完成，未完成的步骤提供直达对应页面的按钮；进度条只统计前五个必需步骤。发布订阅包为可选步骤，签发过订阅包（在线发布或离线签发下载）即视为完成。必需步骤全部完成后，清单缩为一行，只提示尚未完成的可选步骤，并提供「不再显示」；全部步骤完成后清单自动隐藏。未完成时也可以手动隐藏，隐藏状态只保存于当前浏览器。

登录后的任意页面都可以使用全局搜索：在 macOS 上按 ⌘K，在其他系统上按 Ctrl+K，或点击顶栏的「搜索」按钮。搜索框按名称查找用户、Stack、侧栏中的页面、页面内的常用标签页（例如「用量排行」「配置历史」「远端节点源」），以及系统设置的各个分组和其中的每一个设置项；用户还可以按备注查找，Stack 可以按标签查找，页面可以按页面说明中的文字查找，系统设置的每个设置项单独列为一条结果，并标明所在的标签页和分组，例如搜索「停服」得到「每日停服时段」；分组本身也可以按其中的设置项名称和常用说法查找（例如「时区」「SMTP」）。多个关键词以空格分隔，需要同时命中。结果按用户、Stack、页面和系统设置分组，最相关的一组排在最前。上下方向键选择，回车打开，Esc 关闭。未输入关键词时列出最近访问的条目和全部页面，最近访问记录只保存于当前浏览器。选中系统设置分组或设置项后，页面切换到所在的标签页并滚动到该分组。搜索只按名称跳转，不查找配置内容、日志和凭据。从一个用户或 Stack 的详情页直接打开另一个用户或 Stack 时，如果当前页有未保存的修改，同样需要确认后才会离开。

## 4. 日常操作流程

### 4.1 准备依赖

在「依赖」页面安装 xray、mihomo 和 geo 数据。新版本先在暂存目录中验证能否接受当前全部配置，验证通过后才替换现有版本，并逐个重启使用它的服务；重启后服务未能正常运行时自动回滚到原版本。每个组件保留上一个版本，可以手动回滚。

### 4.2 录入用户与 stack

1. 在「系统设置 → 基本」中填写对外地址，即订阅节点默认使用的域名或 IP。
2. 在「用户」页面新建代理用户。新建 stack 的入站需要引用用户，因此至少要先有一个用户。
3. 在「Stack」页面按模板新建 stack。一个 stack 对应一组独立运行的 xray 与 mihomo 进程，端口从「系统设置 → 端口池」中自动分配，凭据随机生成。新建后可以进入编辑页调整入站、出站、上游、代理组和规则。编辑页「基本」中的「运行状态」分为三档：「运行」生成配置并保持 xray 和 mihomo 运行；「保持停止」仍生成配置，但对账时让进程保持停止；「停用」不生成配置，也不参与对账。编辑页中新增的上游自动加入代理组并排在 DIRECT 之前：只有 DIRECT 的代理组会以新上游作为默认选择，含自动测速或负载均衡组的 stack 把新上游加入这些组。外部节点的表单支持 vmess、shadowsocks、socks5 和 http；节点协议选择「其他」时编辑器切换到 YAML，保留 server 和 port 并清空 type，由用户按 mihomo 的代理配置格式填写 type（例如 vless、trojan、hysteria2）和其余字段，YAML 中的 name 被忽略，以上方的名称为准。type 不是表单支持的协议期间表单页保持禁用，type 为空时无法确认；type 改为表单支持的协议后表单页恢复可用，在下拉中改回这些协议时自动回到表单页。打开已有的其他协议上游时直接显示 YAML。stack 改名时，以旧名字开头的入站显示名同步换成新名字，手工改过的显示名保持不变。「Stack」页面顶部的流量拓扑按类别概括整体流向：客户端 → 聚合测速 Stack（auto，聚合多个 edge 测速或负载均衡）→ 独立出口 Stack（edge）→ 出口（上游节点、外部代理、本机直连）→ 互联网，没有的类别不显示。每个节点标出所含 stack 的数量和停用数量，箭头上标出走这条路径的 stack 数量；只经其他 stack 转发、没有自己出口的 stack 在独立出口节点中注明。上方用一句话概括从多少个订阅入站进入、经过哪些类别、从哪些出口出去，下方的图例说明各颜色和线型的含义。悬停节点列出所含的 stack；点击节点后下方列表只显示这些 stack，列表上方显示筛选标签，关闭标签或再次点击该节点即取消筛选。拓扑的展开或收起状态保存于当前浏览器。单个 stack 的详细流向在编辑页的「流量拓扑」标签中查看，它展示从入站、出站、规则、代理组到上游的完整流向，以及引用该 stack 和被该 stack 引用的其他 stack，按编辑中的内容实时绘制。列表的「名称」列在名称下方显示角色、标签和成员。「运行」列在 stack 停用或设为「保持停止」时先显示对应标记，再紧凑显示 xray 和 mihomo 的状态：运行中只显示进程名并标为绿色；其他状态附上简短文字，失败或本应运行却已停止标为红色，按「保持停止」设置停止或尚未生成标为灰色，启动中、停止中分别标为蓝色和黄色；悬停查看服务名和运行时间。「出口 IP」列第一行显示 IPv4 出口，行首圆点是服务端定时检测的结果（绿色正常、黄色待确认、红色异常、灰色未检测或暂停），异常时附文字；有 IPv6 地址时第二行显示；最后一行是城市和运营商简称。服务端检测到的 IPv4 与浏览器查询结果不同时额外提示。完整的地区、运营商和检测详情在悬停提示中查看。列表右上角的「出口 IP」按钮立即重新查询全部启用了 mihomo 的 stack 的出口。

用户基本信息中的「备注」显示在用户列表的名称下方，仅用于管理识别，不覆盖订阅节点名，也不作为展示名模板中的 `.remark`；较长的记录（例如联系方式、付费情况）写在只在用户详情中显示的「内部笔记」中。例如用户 `xc` 备注为 `xiaochen`，加入 `usa1`、`usa3` 的 VMess 入站后，节点仍可分别使用 `usa1 vmess`、`usa3 vmess`。展示名模板依次采用：入站用户单独配置、所选用户档案（default 即用户本身）、Stack 入站、系统设置中的全局模板；均为空时再使用生效的节点备注或 `Stack 名称 + 协议`。普通节点和直连节点使用同一优先级；仅授权直连且不属于任何订阅入站的用户不会借用无关入站模板。同一用户的最终节点名必须唯一。

新建用户时可以选择加入哪些 stack：用户以 default 档案加入所选 stack 全部进入订阅的入站，应用后生效。在 Stack 详情的「入站」中编辑用户列表时，可以点击「添加全部」补齐尚未选择的用户。已有用户的凭据档案和覆盖设置保持不变，新加入的用户使用 default 档案；暂停的用户也会加入，但不会因此恢复。添加结果需先暂存入站编辑，再保存 Stack，应用后才会生效。

### 4.3 应用配置

保存操作只写入数据库，不影响正在运行的代理。Stack 编辑页的入站、上游和代理组在抽屉中编辑，点击「暂存修改」只把改动放回页面，点击页面顶部的「保存」才写入数据库；已保存但尚未应用时，页面顶部注明「已保存，尚未应用」。任何保存成功后，顶栏「待应用变更」的数字随之刷新，悬停可以看到涉及的 Stack 数和变更项数；保存 Stack、用户或系统设置后，如果存在待应用变更，提示中会说明需要应用并提供「查看待应用变更」入口。「待应用变更」显示生成物的差异和将要重启的服务，确认后点击「应用」：系统生成配置、校验，然后重启受影响的服务。每次配置变更都会在「配置历史」中保存一个完整快照，可以比较任意两个版本，或回滚到选中的版本；回滚同样需要应用后才生效。

Stack 编辑页「运行观察 → 诊断」标签页提供三项检查。「出口 IP」经该 stack 的 mihomo SOCKS 监听查询 IPv4 和 IPv6 出口。「上游延迟」调用 mihomo 测试全部代理和代理组访问测试地址的往返延迟，不反映带宽。「下载测速」经该 stack 已应用配置中的 mihomo SOCKS 或 HTTP 监听下载测试文件，测量本服务器经该 stack 出口的下载带宽，不包含用户到服务器这一段；流量按规则和代理组当前的选择出站，结果中列出实际经过的代理链和命中的规则。测速分按时长和按大小两种方式：按时长默认 10 秒，可选 5 到 60 秒，从收到首字节起计时，最多消耗 1 GB 流量；按大小默认 50 MB，可选 10 到 1000 MB，最长 60 秒，到时按已下载的数据计算。测速过程中实时显示当前速度和速度曲线，结束后给出稳定速度、平均速度、峰值速度、下载量、用时和首字节时间：稳定速度排除首字节后的第一秒，平均速度按全部下载时间计算，峰值速度取一秒窗口内的最高值。默认测速地址为 Cloudflare 的测速下载地址，也可以填写其他 http 或 https 地址：地址中的 `{bytes}` 替换为单次请求的字节数，单次最多 50 MB；不含 `{bytes}` 的地址重复下载直到满足停止条件。测速会消耗上游流量，auto stack 的测速流量计入 edge stack 的 relay 入站。所有 stack 共用本机带宽，同一时间只允许进行一个测速。stack 需要已应用过配置且 mihomo 正在运行。

### 4.4 暂停与恢复用户

用户详情页分为五个标签页。「基本」顶部是当场生效的启用开关，其下为名称、备注、内部笔记，以及额度、重置周期、每日用量阈值、到期时间和每日停服时段；流量额度和每日用量阈值的输入单位默认为 GB，下方分别显示本周期（或累计）和今日的已用量，到期时间可以用「+1 个月」「+3 个月」「+1 年」快捷延长，延长从当前到期时间和现在两者中较晚的一个开始计算。「订阅」包含订阅链接与预览、订阅 token 和展示名模板，并列出该用户订阅的节点来源：入站引用该用户的 stack 数（其中尚未应用的数量）、手工节点数和远端节点源。「凭据」包含 default 档案的 UUID、SS 密码和其他凭据档案，每个档案单独成块，删除前需要确认。「接入」每个 stack 一行，列出引用该用户的入站及所用档案，右侧是两个开关：「加入」开关标注「需应用」，「启用」开关标注「当场生效」，只在已加入的 stack 上显示。打开「加入」时，用户以 default 档案进入该 stack 全部进入订阅的入站，已有的引用保持原有档案和覆盖设置，用户原本不在该 stack 中时同时清除该 stack 上残留的暂停。关闭「加入」时，经确认后从该 stack 的全部入站中移除该用户；该 stack 上的暂停予以保留，使用户在移出应用之前保持暂停。加入和移出修改 stack 的入站，需要应用后生效；该 stack 没有进入订阅的入站时不能加入，入站不接受该用户（例如 2022 系列 shadowsocks 入站要求对应长度的密钥）或移出后入站没有用户时，提示中写明具体入站和原因。关闭「启用」即在该 stack 上暂停该用户，打开即恢复，均当场生效；用户整体停用期间不能切换。需要使用其他档案或只加入部分入站时，在 stack 的「入站」中编辑。订阅节点只来自各 stack 已应用的版本：入站已引用该用户、但该 stack 尚未应用或在用户加入入站之后没有重新应用时，该行标记「未应用」，「订阅」和「接入」两页顶部给出提示和「查看待应用变更」入口；用户没有任何订阅节点时，提示说明原因，并指出订阅端会对该用户返回 `not_found`。应用完成后提示自动消失。「用量」显示今日和本周期用量及其与阈值、额度的比例、各 Stack 用量和趋势。页面顶部的摘要在所有标签页显示用户状态、今日用量（设置了每日阈值时一并显示阈值）、额度使用情况和到期时间，以及保存按钮。标签页上的黄点表示该页有未保存的修改，红点表示该页有校验错误，保存失败时自动切换到出错字段所在的标签页。启用开关、各 stack 暂停以及加入和移出 stack 不需要点击保存，不计入未保存的修改。当前标签页记录在地址中（例如 `?tab=subscription`），刷新或分享链接后回到同一页。

本机 stack 之外进入订阅的节点在「订阅 → 额外节点」页面管理，分为两个标签页：「手工节点」按用户归属手工录入，「远端节点源」从另一台 proxystack-web 拉取其导出的节点并按用户名分给本机同名用户。标签页名称后显示各自的数量。用户详情的「订阅」标签页显示该用户的手工节点数，并可直接打开只显示该用户节点的列表。

在用户列表或用户详情中暂停用户后，系统立即通过 xray 的用户管理接口把该用户从代理端移除，配置保持不变，无需应用；恢复时立即加回。暂停可以针对全部 stack，也可以只针对部分 stack。订阅中对应节点的去掉和加回随订阅包生效：开启自动发布时随即发布，否则在下次发布后生效。用户的额度超限、每日用量达到阈值或到期时，系统按设置自动暂停并发送邮件通知。

每日停服时段让用户在每天固定的时间段内自动暂停，时段结束后自动恢复。全局时段在「系统设置 → 流量」中设置，可以设置多段，每段由开始和结束时刻组成，结束早于开始表示跨零点（例如 23:00 至次日 06:00），首尾相接或重叠的时段合并为一段连续停服；留空表示不停服。时段按「基本」分组中的时区计算。用户详情「基本」标签页的「每日停服时段」有三种取值：「跟随全局」使用系统设置中的时段，「自定义」使用为该用户单独设置的时段且不受系统设置影响，「不限制」使该用户不受停服时段约束。系统在每轮流量采集后判定，因此暂停和恢复相对时段边界最多延迟一个采集间隔；保存系统设置或用户后立即重新判定。已停用的用户不进入停服时段暂停。停服时段暂停与其他自动暂停一样不修改配置、无需应用，也不改变订阅内容；它是预期行为，不发送邮件通知。每次进入或离开停服时段，审计日志各记录一条汇总，列出受影响的用户。开启「暂停时断开现有连接」时，进入停服时段后只重启入站引用了被暂停用户的 stack 的 xray，切断已建立的连接，否则已建立的连接会持续到自然断开。用户处于停服时段暂停时，「用量」标签页提供「本时段放行」：放行持续到这段连续停服结束，之后的停服时段照常暂停，放行期间页面显示放行的截止时间。

### 4.5 发布订阅

1. 在「订阅模板」页面可以查看或自定义 Clash、Premium Clash 和 Surge 三种格式的模板。格式标签上标出已自定义的格式，有未保存修改的格式显示圆点。内置模板只读，点击「基于内置模板修改」后在其副本上编辑，「恢复内置模板」清空自定义内容，「撤销本页修改」放弃当前格式未保存的修改。「模板语法与可用变量」列出模板可用的变量和过滤器，点击变量名即复制对应的表达式。预览按所选用户的节点和当前编辑内容自动生成，可以下载到文件。内容区足够宽时模板与预览并排显示，较窄时用「模板 / 预览」切换。保存按钮和 Cmd+S（Windows 与 Linux 为 Ctrl+S）一次保存全部格式的修改，保存后订阅立即使用新模板。
2. 需要在线发布或部署时，先在「SSH 发布与部署」生成管理端 SSH Ed25519 密钥。同一公钥可以安装到多台订阅端，私钥只保存在管理端，不通过 API 或页面返回。
3. 添加订阅端目标，填写 SSH 地址、SSH 用户、Host Key 算法与 SHA256 指纹、订阅端 HTTP 端口和来源名。远端 HTTP 主机固定为 `127.0.0.1`，不能配置成其他地址。
4. 按页面的逐步说明，在订阅端完成以下配置：

   - 把页面生成的受限 `authorized_keys` 条目加入 SSH 用户的 `~/.ssh/authorized_keys`。`permitopen` 只允许向指定的订阅端回环端口做正向转发，同时保留部署命令执行能力。
   - 按页面给出的 `sshd_config` 片段限制转发目标、TTY、X11 和 Agent Forwarding。应用配置前先执行 `sshd -t`，然后 reload sshd。
   - 非 root SSH 用户按页面命令配置受限的 `sudo -n`。由于部署过程会上传并以 root 执行新二进制，这个 SSH 公钥具有部署级 root 权限，必须使用专用账号并严格保护私钥。
   - 首次通过 SSH 安装或更新时，管理端会在部署完成后自动配置发布 Secret，不要在订阅端尚未安装二进制时执行命令。若使用离线安装或需要手工重置，先完成订阅端安装，再执行 `sudo proxystack-web sub source set-publish-token 来源名`，按提示粘贴页面显示的发布 Secret。订阅端只保存 Secret 的 SHA-256 哈希；每个目标使用独立 Secret。
   - 通过独立可信渠道核对 SSH Host Key 指纹。例如可以在订阅端本机运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`，不要只信任管理端首次网络扫描得到的结果。

5. 回到目标列表先点击「检测部署」，检查 Linux、CPU 架构、`sudo -n`、安装状态和当前版本；随后可安装、更新或回滚。管理端下载对应架构的 Release 裸二进制并校验 SHA256，通过 SSH 上传后调用远端同一个 `sub deploy` 实现。更新时管理端先比较订阅端当前版本与最新稳定版：订阅端服务正在运行且版本已是最新（或更新）时，跳过下载和上传，只重新写入发布 Secret；版本较旧、服务未运行或版本号无法比较时，按完整流程更新。上传前检测订阅端是否有 gzip 命令：有则在管理端压缩程序后上传、在订阅端解压，上传量约为原来的四成；没有则原样上传，并在任务日志中提示安装 gzip（Debian/Ubuntu 执行 `apt install gzip`，RHEL 系执行 `dnf install gzip`）。「检测部署」发现订阅端没有 gzip 时同样给出提示。无论是否压缩，远端安装前都会校验程序的 SHA-256。部署任务的日志分阶段记录耗时：下载程序的大小和用时、SSH 连接用时、上传进度（约每 5 秒记录一次已传大小、比例、速度和预计剩余时间）与上传总用时、远端安装（校验、安装、启动服务并等待健康检查）用时，以及写入发布 Secret 的用时，便于判断耗时集中在哪个阶段。
6. 点击「测试」检查 SSH TCP、Host Key、SSH 公钥认证、到 `127.0.0.1:<订阅端端口>` 的正向转发、`/health` 健康状态和发布 Secret。全部通过后，在「发布订阅包」页面选择「SSH 在线发布」。

「SSH 发布与部署」页面顶部显示在线发布进度，「发布订阅包」页面在选择「SSH 在线发布」且已有启用的订阅端时同样显示：生成 SSH 密钥、添加订阅端、部署、测试、签发并发布。前四步只要有一个启用的订阅端完成即视为完成；最后一步要求最近一次签发已成功送达，并且之后订阅内容没有变化。每一步显示完成、进行中或失败，失败时说明是哪个订阅端出错。当前步骤只提供一个主操作，例如「检测部署 sub1」「测试 sub1」；该操作属于另一个页面时，按钮直接跳转过去。「发布订阅包」页面没有启用的订阅端时，提示中提供「去添加订阅端」和「改用离线签发下载」两个入口；订阅端尚未就绪时，对应行提供「去处理」入口。发布方式的选择保存于当前浏览器；没有保存过选择且没有就绪的订阅端时，页面默认选中「离线签发下载」。

在线发布只要求管理端能够连接订阅端的 SSH 端口。订阅端不需要额外监听隧道管理端口，也不会主动连接管理端；订阅导入 HTTP 接口仍可只监听回环地址。管理端严格校验已配置的 SSH Host Key，并禁止 HTTP 重定向。

「更多」菜单中的「卸载订阅服务」通过 SSH 卸载订阅端：删除订阅服务和程序、配置、已导入的订阅包以及服务账号，数据不保留，重新部署后再发布一次订阅包即可恢复。确认时需要输入订阅端名称，可以选择卸载成功后删除这个订阅端的配置。卸载在后台任务中执行，先检测远端状态：未安装时不做任何改动；程序已被删除但数据仍在时，下载最新正式版的程序完成删除。卸载失败时保留订阅端配置，可以重试。同一 SSH 主机和端口上还有其他订阅端时，它们共用同一个安装目录，面板拒绝卸载，需要先删除其中一个订阅端，或在主机上手动卸载。SSH 公钥、sudoers 规则和 sshd 限制配置不会被卸载删除，需要按清理说明手动处理。「删除订阅端」只删除管理端保存的配置并下载清理说明，勾选「同时卸载远端订阅服务」时改为执行上述卸载，成功后再删除配置。

普通目标列表只显示 Secret 掩码。「完整配置」只展示 `authorized_keys`、`sshd_config` 和 sudoers 等非敏感配置；需要查看当前 Secret 时，单独点击操作列的「查看 Secret」，每次查看都会记入审计日志，响应禁止缓存，窗口关闭后页面清除本次显示的明文。怀疑 Secret 泄露时再执行轮换并到订阅端重新运行 `set-publish-token`。轮换后管理端立即改用新 Secret，在订阅端更新前在线发布会失败；订阅端完成更新后，旧 Secret 才会失效。

目标来源名必须与管理端「系统设置 → 订阅」中的当前来源名一致。修改管理端来源名后，需要同步更新订阅端信任来源和目标配置，并轮换、重新配置该目标的发布 Secret。

无法建立 SSH 连接或需要保持网络隔离时，在「发布订阅包」页面选择「离线签发下载」，把文件拷贝到订阅端并执行以下命令，或者直接放入订阅端的 `inbox` 目录：

```bash
sudo proxystack-web sub --dir /opt/proxystack-web-sub import FILE
```

订阅端拒收签名不符、来源与 Secret 绑定不符或序号更旧的订阅包。相同序号且原始文件完全一致时返回已导入，相同序号但内容不同时拒绝。HTTP、CLI 和 `inbox` 导入共用跨进程文件锁与原子替换，避免并发导入使旧包覆盖新包。订阅内容在上次签发之后发生变化时，「发布订阅包」页面会给出提示。启用且未到期的用户没有订阅节点，或者有 stack 尚未应用时，该页面在签发前列出这些用户及原因，并提供「查看待应用变更」入口。暂停用户在代理端立即生效，订阅中对应节点的移除随下一次发布生效。

「系统设置 → 订阅 → 自动发布订阅包」默认开启。开启时，管理端在订阅内容发生变化后自动签发订阅包，并发布到全部启用、属于当前来源、已部署且在部署后测试通过的在线订阅端；引起变化的操作包括应用 stack、暂停或恢复用户、修改用户、手工节点、模板和订阅设置，以及远端节点源同步。连续的改动在几秒内合并为一次发布，后台每分钟还会检查一次，新就绪或落后于最近一次签发的订阅端也会收到发布。每次自动发布都发往全部就绪的订阅端，以后台任务执行，操作者记为「自动发布」，并与手动发布一样写入审计日志。同一内容发往同一组订阅端未能全部送达时，重试间隔从 10 分钟起逐次翻倍，最长 6 小时；内容或订阅端组合变化时立即重试。有 stack 的已应用版本在构建订阅时被整体跳过时，自动发布暂停，以免签发缺少这些节点的订阅包；「发布订阅包」页面说明原因，修复后自动恢复，确认需要时也可以在该页面手动签发。没有就绪的订阅端时不会自动发布，离线订阅端仍需在「发布订阅包」页面签发下载。关闭后订阅包只在该页面手动签发。「发布订阅包」页面顶部显示自动发布是否开启、目标订阅端数量以及暂停的原因。升级到包含自动发布的版本后，自动发布默认开启，尚未发布的订阅改动会在一分钟内发布到就绪的订阅端。

多台管理端可以向同一个订阅端发布，节点按用户名合并。在订阅端执行 `proxystack-web sub source add NAME PUBLIC_KEY` 信任新的来源。

用户列表和用户详情提供的订阅链接包含用户名，例如 `/s/eagle/<token>/clash`，Premium Clash 和 Surge 的末段分别为 `premium`、`surge`。用户名用于识别，仍由随机 token 鉴权；用户改名后，已分发的链接仍可使用，重置 token 并发布导入后旧 token 失效。订阅端兼容原有 `/s/<token>/<格式>` 链接；使用带用户名的新路径时，管理端与订阅端都需要升级到支持该格式的版本。

## 5. 流量、通知与运维

「系统设置」按用途分为五个标签页：

| 标签页 | 分组 |
| --- | --- |
| 基本 | 基本（对外地址、面板地址、时区）、安全 |
| 订阅 | 订阅 |
| 流量与通知 | 流量、通知 |
| 下载与依赖 | 下载代理、依赖源 |
| 高级 | 默认值（日志级别、Xray API、API 服务、stats、policy 及其统计开关）、端口池、节点导出 |

保存按钮对全部标签页生效。标签页上的黄点表示该页有未保存的修改，红点表示该页有校验错误，保存失败时自动切换到出错字段所在的标签页。当前标签页记录在地址中（例如 `?tab=advanced`）；其他页面链接到某个分组（例如 `?section=notify`）时，打开该分组所在的标签页并滚动到该分组。

页面顶部的搜索框按设置项名称、说明和选项文字查找，多个关键词以空格分隔、需要同时命中。搜索覆盖全部标签页：只显示命中的分组，标签页名称后显示该页命中的分组数，当前标签页没有结果时自动切换到第一个有结果的标签页；清空搜索后显示全部分组。只在特定选项下出现的字段（例如依赖源选择自定义 URL 后才出现的 sha256）需要先切换到对应选项才能被搜到。

每个分组标题右侧标明保存后的生效方式，悬停查看详情：

| 标签 | 含义 | 分组 |
| --- | --- | --- |
| 立即生效 | 保存后马上用于后续操作 | 端口池（只影响之后分配的端口）、节点导出、通知、依赖源、下载代理 |
| 需要应用 | 进入「待应用变更」，应用后才影响运行中的代理 | 默认值 |
| 部分需要应用 | 开关流量监控需要应用，其余项立即生效 | 流量 |
| 随订阅包生效 | 重新发布订阅包后生效；开启自动发布时保存后自动发布 | 订阅 |
| 部分随订阅包生效 | 对外地址随订阅包生效，面板地址和时区立即生效 | 基本 |
| 影响校验 | stack 的保存和应用按新规则校验 | 安全 |

「安全」分组的「公开入站必须设密码」开启时，监听在非本机地址的 SOCKS5 和 HTTP 入站没有设置密码，stack 的保存和应用都会校验失败；监听在本机地址的入站不受此限制。关闭前需要确认，关闭后任何能访问该端口的人都能使用代理。

- **流量口径**：流量统计有两种口径。按用户统计时使用用户计数，同一用户的全部凭据档案合并计算，用户从哪个 stack 接入，流量就记在哪个 stack。按 Stack 统计时使用各 stack 的入站计数；auto stack 的流量经 edge stack 的 relay 入站出网，会在 edge stack 再计一次，因此跨 stack 的合计不含 auto stack，auto stack 在列表中标为「不计入合计」。stack 的入站总量中无法归属到用户的部分分为两类：「经 relay 入站」主要是 auto stack 转发过来的用户流量，这些用户已在 auto stack 计入；「共享账号等」来自 SOCKS5 / HTTP 共享账号。统计按系统时区的自然日和日历月计算。
- **总览**：「总览」显示今日和本月的全部流量（各 stack 入站之和，不含 auto stack），并与昨日同时段、上月同期对比，对比取上一期的同等已过时长；卡片下方注明其中归属到用户和未归属的部分。页面还显示当前速率、正在使用的用户数、最近一小时实时速率（按分钟取平均，上行和下行堆叠显示）、按最近一次采集的速率列出的占用带宽最高的五个用户、今日和本月用量前五名，以及各 Stack 的今日入站、本月入站和本月未归属到用户的流量。最近 24 小时内有数据不完整的时段时，页面顶部给出提示。用户列表的今日用量和周期用量可以排序，每日阈值和额度下方显示已用百分比，达到 80% 标黄，达到 100% 标红。
- **流量明细**：「流量明细」分为「按用户」「按 Stack」和「排行」三个标签页。「按用户」和「按 Stack」共用同一组条件。时间可以从快捷时间段中选择：今日、昨日按小时，近 7 天、近 30 天、本月、上月按日，近 12 个月、今年按月；也可以在日期选择器中指定任意范围，范围旁显示所含的时间桶数量。「‹」「›」把范围整体前移或后移一段，从自然日、自然月、自然年开头起算的范围按完整的自然日、月、年移动，例如今日移到昨日全天，本月移到上月全月；后一段的起点晚于当前时间时不能后移。粒度可选小时、日、月、年，切换粒度时保留所选时间段并换算到新粒度，换算后时间桶过多时改用新粒度的默认范围。可以筛选用户和 Stack。「按用户」每个用户一行，展开后列出各 Stack 和各凭据档案的用量；「按 Stack」每个 stack 一行，展开后列出各用户以及「经 relay 入站」「共享账号等」两行未归属流量。「按 Stack」筛选了用户时改用这些用户的计数，各 stack 之间没有重复，合计包含 auto stack。只筛选一个用户或一个 stack 时，趋势图按它的明细拆分。打开「对比上一期」后显示上一期同等时长的用量和变化比例，当前周期未结束时上一期只取同等的已过时长。查询范围在分钟明细保留期内时显示峰值速率，即单分钟平均速率的最大值。零用量的用户和 stack 默认隐藏，打开「显示零用量」后列出。已删除的用户和 stack 保留最后一次保存时的名字并标为「已删除」。所选粒度的明细超出保留期时，页面说明该粒度的数据从何时开始，趋势图以灰色标出没有明细的时间段，并提供切换到更粗粒度的按钮。查询结果可以导出 CSV。「排行」可选今日、昨日、本月、上月或自定义日期范围，可以只统计一个 Stack，按合计、上行或下行排序，列出名次、环比和与上一期相比的名次变化；零用量的用户默认隐藏，无法归属到用户的流量不参与排行。各标签页的条件写入页面地址，刷新或分享链接后打开同一视图。采集间隔和数据保留期在「系统设置 → 流量」中设置。
- **数据缺口**：系统记录流量数据不完整的时段，在总览、流量明细和排行中提示，并在趋势图中以阴影标出。缺口分为两类：「流量丢失」指 xray 在两次采集之间重启或停止，或 stack 未开启统计接口，这段时间的流量没有采集到；「延后计入」指读取计数失败或管理服务未运行，这段时间的流量在恢复采集时计入恢复的时刻。缺口记录随流量明细按保留期清理。
- **详情用量**：用户详情的「用量」标签页打开期间每 10 秒自动刷新，切换到其他标签页后停止，也可手动刷新，不会覆盖正在编辑的用户信息。该页的趋势图可按天查看近 30 天用量，也可按小时查看最近 24 小时、48 小时或 7 天的用量，按 Stack 分色堆叠，小时按统计时区的整点汇总；选择某个 Stack 后图表只显示该 Stack。「在流量明细中查看」打开「流量明细」的「按用户」标签页并预先选好该用户、当前粒度和所选 Stack，用于查看更长的时间范围或导出 CSV。Stack 详情的「用量统计」显示本 Stack 的今日、本月和近 30 天用量，每 10 秒刷新；可以指定用户或清空选择查看全部用户。全部流量使用入站计数，指定用户时合并其全部凭据档案。查看全部用户时，「各用户用量明细」列出每个用户在三个时间段的用量，入站总量中未归属到用户的部分列在最后，分为「经 relay 入站」和「共享账号等」两行。「用量趋势」可查看近 30 天的日用量，或最近 24 小时、48 小时、7 天的小时用量，按用户分色堆叠，不含未归属到用户的流量，指定用户时只显示该用户。「在流量明细中查看」打开「流量明细」并预先选好本 stack 和当前粒度：查看全部用户时打开「按 Stack」标签页，指定用户时打开「按用户」标签页。统计按系统时区计算，日明细受保留策略影响；离开统计页面后停止轮询，刷新失败时保留上次成功获取的结果并提示。
- **通知**：额度超限、每日阈值触发和到期暂停等事件通过「系统设置 → 通知」中配置的 SMTP 服务器发送邮件。邮件通知未开启或未在通知事件中勾选的事件只记录、不发送，「通知记录」页面的说明栏写明是哪一种原因。发送失败的记录在「通知记录」页面可以手动重发。
- **定时任务**：「定时任务」页面列出数据库备份、流量数据清理、geo 数据更新、依赖版本检查、依赖自动升级、远端节点源同步、对账和配置导出邮件等内置任务，可以修改计划、超时或立即执行。
- **健康检查**：「健康检查」页面汇总依赖、服务运行状态、配置漂移、端口占用、流量采集、数据库、备份和磁盘空间等检查项，每项给出通过、警告或失败的结论和处理建议。
- **审计日志**：管理员的登录、登录失败、改密、两步验证变更、配置修改、查看明文凭据、下载备份等操作都记入「审计日志」。

## 6. 账号安全

### 6.1 两步验证

在右上角账号菜单的「账号安全」页面开启两步验证：

1. 点击「开启两步验证」，页面显示二维码和对应的密钥。
2. 用验证器应用（例如 Google Authenticator、Microsoft Authenticator 或 1Password）扫描二维码；无法扫码时手工输入密钥，类型选择基于时间、6 位、30 秒。
3. 输入应用显示的验证码并确认。开启成功后，该管理员在其他设备上的登录全部失效。

开启后，登录时需要在密码之后再输入验证码。验证码允许前后各 30 秒的时钟偏差，每个验证码只能使用一次。关闭两步验证需要同时提供当前密码和验证码。

验证器设备丢失时，在服务器上执行以下命令，在重置密码的同时关闭两步验证：

```bash
sudo proxystack-web admin reset-password --disable-totp
```

### 6.2 登录保护

| 规则 | 说明 |
| --- | --- |
| 账号锁定 | 同一账号连续 5 次登录失败（密码错误或验证码错误）后锁定 15 分钟，锁定期间即使密码正确也无法登录 |
| 来源地址限速 | 同一来源地址 15 分钟内认证失败 10 次后，15 分钟内拒绝该地址的登录与重置请求，响应状态码为 429，并在 Retry-After 响应头中给出等待秒数 |
| 会话有效期 | 24 小时没有操作后会话失效；持续使用的会话在创建 7 天后同样失效，需要重新登录 |
| 会话续期 | 只有管理员的实际操作续期会话：修改类请求，以及管理员键盘或鼠标操作后一分钟内面板发出的请求。页面在后台定时刷新数据不续期，无人操作的页面在 24 小时后同样失效 |
| 到期提醒 | 距离会话失效不足 30 分钟时，顶栏显示剩余时间；不足 5 分钟时再弹出一次提醒。因闲置即将失效时，任意操作即可续期；因创建满 7 天即将失效时，可以在提醒中直接重新登录 |
| 失效后重新登录 | 会话失效后，面板在当前页面弹出登录框，重新登录后留在原页面，未保存的修改保留；失效时未完成的操作需要重新执行。也可以选择换个账号，前往登录页 |
| 会话注销 | 修改密码或开启两步验证后，该管理员的其他会话全部失效；重置密码后全部会话失效 |

来源地址的失败计数保存在内存中，管理服务重启后清零；账号锁定状态保存在数据库中。不存在的用户名、错误的重置链接，以及已登录状态下改密或关闭两步验证时输错密码，均计入来源地址的失败次数。

### 6.3 凭据保护

- 管理员密码以 argon2id 哈希保存。会话 cookie 设置 HttpOnly 与 SameSite=Strict，所有修改类请求都要求携带 CSRF token。
- 面板默认以遮蔽值显示代理凭据、订阅 token 和 SMTP 密码等敏感字段，点击「显示」时单独请求明文，并记入审计日志。
- 日志中不记录密码、token、uuid 和完整订阅内容。
- 管理服务以普通用户身份运行，只能启停 `psw-xray@*` 与 `psw-mihomo@*` 两类代理服务，无法直接获得 root 权限。

## 7. 升级

### 7.1 升级管理端

「版本与升级」页面并排显示当前版本和最新正式版。打开页面时自动检查一次新版本，也可以点击「重新检查」；有新版本时显示更新说明。xray 与 mihomo 由独立的 systemd unit 承载，管理服务重启期间代理流量不中断。下载经由「系统设置 → 下载代理」。

**立即更新**：点击「立即更新到 vX」并确认后，弹窗按以下阶段显示进度，失败时停在出错的阶段并提供任务日志入口：

1. 查找版本：查询发布信息。
2. 下载：显示进度条、已下载与总大小、下载速度和预计剩余时间。
3. 校验：核对发布附带的 SHA-256。
4. 替换程序：试运行新程序，确认可以执行后原子替换，并保留上一版本。
5. 重启管理服务：页面短暂断开。
6. 确认新版本：等待重启后的服务报告新版本，确认后页面自动刷新。

**预约升级**：适用于新版本即将发布、希望发布后自动升级的场景。目标版本可以选择「最新正式版」或指定版本号（例如 v0.6.1）；等待时长可选 5 分钟、30 分钟、1 小时、6 小时、24 小时或自定义分钟数（最长 24 小时）；检查间隔可选 10 秒、20 秒、1 分钟或 5 分钟。表单下方用一句话说明预约的效果。目标为最新正式版时，等待期间只要发布了比当前更新的正式版就升级；等满时长仍没有则结束预约。

预约由管理服务在后台执行，不需要保持页面打开，服务重启后预约继续。等待期间页面显示已过去的等待时间、剩余时间、截止时间、下次检查倒计时和上次检查时间，可以随时取消；开始升级后显示与立即更新相同的阶段进度。预约结束后保留结果（已升级、等待结束或失败原因），可以清除。预约进行中不能同时执行立即更新。开发模式下管理服务不能自动重启，立即更新和预约升级都不可用。

### 7.2 下载代理

管理端的全部对外下载，包括依赖安装与升级、管理端自更新以及版本检查，统一使用「系统设置 → 下载代理」中的设置，不读取系统环境变量。可选模式如下：

| 模式 | 说明 |
| --- | --- |
| 直连 | 默认模式，直接访问 GitHub |
| 经指定 stack 的 mihomo 监听 | 通过本机某个 stack 的 mihomo SOCKS 或 HTTP 监听出站，要求该 stack 正在运行 |
| 自定义代理 | 填写 HTTP 或 SOCKS5 代理的地址、端口和可选的用户名密码 |

保存前可以点击测试，用表单当前的值请求一次 GitHub。执行升级时，作业日志的第一行记录本次使用的代理，其中的密码已遮蔽。

## 8. 备份与迁移

### 8.1 备份

- 定时任务「数据库备份」定期把数据库快照写入 `/opt/proxystack-web/backups`，超过保留份数的旧备份自动删除。
- 定时任务「配置导出邮件」默认在每月 1 日和 15 日 04:30 执行，也可以在「定时任务」页面点「立即执行」。任务导出全部配置（内容与「导出全部配置」相同），作为 YAML 附件通过「系统设置 → 通知」中的 SMTP 服务器发出。收件人在任务的「编辑」中填写，留空时发给 SMTP 的发件人地址。附件中的凭据用任务中设置的加密口令加密，口令至少 8 个字符，在「导入配置」时输入，请另行妥善保存。系统设置中的邮件通知未启用或任务未设置口令时，本次执行记为「跳过」并在执行记录中说明原因；发送失败记为「失败」，等到下一次计划时间再发送。
- 在「备份」页面可以导出整机迁移包。迁移包包含数据库中的全部数据：配置、凭据、订阅 token、流量记录、审计日志和管理员账号，不含 xray、mihomo 与 geo 文件。迁移包默认以口令加密。
- 在命令行导出迁移包：`sudo proxystack-web backup --output FILE`。

备份文件和迁移包包含全部凭据、订阅 token 和管理员账号，下载前页面会再次提示，下载操作记入审计日志，请保存在可信位置并及时删除副本。

「备份」页面把会替换现有数据的操作（导入配置、恢复迁移包）集中放在页面末尾，并以醒目的边框标出。导入配置选择「替换全部」，或者执行恢复迁移包时，页面先列出影响范围，要求输入确认词（分别为「替换全部」和「恢复」）后才能执行。替换全部的影响范围包括：现有用户、Stack、手工节点和远端节点源整体替换为文件内容，以及替换后的用户数和 Stack 数。恢复的影响范围包括：恢复后的数据规模、凭据和订阅 token 的替换、管理员账号与面板监听设置的去向、管理服务重启和代理是否启动。

### 8.2 迁移到新机器

推荐在新机器上安装时直接恢复：

```bash
curl -fsSL https://raw.githubusercontent.com/sunliang711/proxystack-web/refs/heads/main/deploy/install.sh \
  | sudo bash -s -- --restore /root/backup.pswbak
```

脚本从终端读取迁移包口令（不回显），恢复后使用源实例的管理员账号登录。随后在「依赖」页面按源实例的版本安装 xray、mihomo 与 geo，安装完成后系统自动重新生成配置并启动 stack。

也可以在已安装的实例上通过「备份」页面上传迁移包恢复。恢复会整体替换当前数据库，执行前自动备份当前数据库，然后重启管理服务。

## 9. 救援命令

以下命令需要以 root 或服务账号身份在服务器上执行。它们直接写入数据库，不需要重启服务。

| 命令 | 作用 |
| --- | --- |
| `proxystack-web admin reset-password` | 生成新的随机密码并打印；`--password-stdin` 从标准输入读取指定密码。下次登录必须修改密码 |
| `proxystack-web admin reset-link` | 打印一次性密码重置链接，15 分钟内有效，只能使用一次 |
| `proxystack-web admin set-listen --listen ADDR --port PORT` | 修改面板监听地址或端口，重启管理服务后生效 |
| `proxystack-web info` | 显示面板地址和订阅包签名公钥 |

`reset-password` 与 `reset-link` 都可以附加 `--disable-totp`，同时关闭两步验证。重置成功后，该管理员的全部会话立即失效，登录失败计数和锁定状态清零，操作记入审计日志。

## 10. 卸载

```bash
curl -fsSL https://raw.githubusercontent.com/sunliang711/proxystack-web/refs/heads/main/deploy/uninstall.sh \
  | sudo bash -s -- --role all
```

`--role` 可选 `panel`、`sub` 或 `all`，默认卸载已安装的全部角色：停止并删除服务、unit 文件、polkit 规则和命令链接，保留管理端的 `data` 与 `backups` 目录，以及订阅端的配置和已导入的订阅包。附加 `--purge` 时删除整个安装目录和服务账号。

## 11. 故障排查

| 现象 | 处理方法 |
| --- | --- |
| 忘记面板地址 | 在服务器上执行 `sudo proxystack-web info` |
| 忘记密码或验证器设备丢失 | 执行 `sudo proxystack-web admin reset-password`，设备丢失时附加 `--disable-totp` |
| 登录提示账号已锁定 | 等待 15 分钟，或执行 `reset-password` 立即解除 |
| 登录提示失败次数过多 | 来源地址被暂时限速，按提示的时间等待后重试 |
| 修改监听地址后无法访问面板 | 在服务器上执行 `sudo proxystack-web admin set-listen` 恢复，然后重启管理服务 |
| 依赖下载失败 | 在「系统设置 → 下载代理」中配置并测试代理 |
| stack 未运行或配置异常 | 查看「健康检查」页面和 stack 编辑页的「诊断」「日志」标签页 |
| 订阅端返回 404 或旧内容 | 返回 `subscription not found` 时，该用户在订阅包中没有节点或已停用、到期：查看用户详情「订阅」页的提示，按提示应用相关 stack 后重新发布。其他情况执行 `proxystack-web sub --dir /opt/proxystack-web-sub status` 查看已导入的订阅包，重新发布并导入 |
| 页面文字重复显示，或切换页面后标题已变但正文仍是上一页 | 网页翻译类浏览器插件改写了页面内容。面板已声明无需翻译，正文在下一次切换页面时整体重建；仍然出现时，在该插件中把面板地址加入不翻译列表，然后刷新页面 |

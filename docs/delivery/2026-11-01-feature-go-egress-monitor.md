# Stack 出口定时检测与邮件通知

## 背景与行为

新增「Stack 出口检测」定时任务，默认每两分钟执行，每次查询超时 12 秒。首次查询的 IPv4、IPv6 都无法获得合法地址时，等待 1 秒后重试，默认额外重试 3 次（最多查询 4 次）。任意一次查询获得有效地址即结束本轮；所有尝试都失败时生成一次故障事件；任一地址族恢复后生成一次恢复事件。持续故障期间不重复生成邮件，首次正常检测不发恢复通知。

仅检测已启用、实际运行且具有已应用 Mihomo SOCKS 监听的 Stack。读取已应用版本的监听地址和认证，保存但尚未应用的配置不影响探测。仅 Xray、缺少已应用监听的 Stack 显示不支持；主动停止暂停检测，不视为故障或恢复。单个 unit 状态读取失败只跳过该 Stack，不影响其他 Stack，也不累计出口失败次数。

同一 Stack 的 IPv4/IPv6 并发探测，每个地址族支持探测源回退；不同 Stack 最多四个同时探测，任务不重叠。每次重试前固定等待 1 秒，等待支持上下文取消。整个任务取消或超时不计入出口失败；任务总超时需覆盖所有 Stack 的查询、重试和等待。检测过程中应用、启停或删除 Stack 时丢弃过期结果。

## 配置与界面

- 「定时任务 → Stack 出口检测」可配置调度、任务总超时、额外重试次数（0～10，0 表示仅首次查询）和每次查询超时（1～60 秒），支持手动执行。
- 出口检测计划支持每分钟、每 2 分钟、每 5 分钟预设及自定义 cron。
- 复用系统 SMTP 配置、收件人和通知队列。启用邮件总开关并勾选「Stack 出口异常」「Stack 出口恢复」后发送对应邮件；既有实例不自动增加事件勾选。
- 邮件包含实例、Stack、检测时间、失败原因或故障时长、恢复地址和详情链接。通知历史可跳转到对应 Stack。
- Stack 列表每 10 秒读取后台检测结果，显示状态与检测时间。该状态独立于浏览器的出口 IP 缓存，手动刷新 IP 不累计后台失败次数。
- 新增已鉴权只读接口 `GET /api/runtime/egress-health`；调用该接口不会触发探测。

## 存储与并发

迁移 `00011_stack_egress_health.sql` 增加健康状态表及通知的 Stack/事件编号字段。状态和通知在同一事务保存，重启后保留最近故障轮次的查询失败次数、故障事件编号和告警标记，防止重复告警。

迁移 `00012_egress_retries.sql` 将旧默认一分钟计划调整为两分钟，增加默认重试 3 次并移除旧阈值参数，保留自定义计划、任务开关及查询超时。旧的跨周期失败计数清零，尚未确认的故障恢复为待检测；已确认故障的事件编号、告警状态和故障起始时间继续保留。

邮件发送复用既有重试策略，并与健康状态切换串行协调。恢复后撤销尚未发出的旧故障事件，旧事件不能手动重发；删除 Stack 后不再发送其待处理通知。等待 SMTP 时不占用运行时锁，避免阻塞 Stack 操作。

无新增外部依赖、环境变量或后台服务。

## 验证与评审

- 全量 Go 测试、前端类型检查和生产构建。
- 出口状态与通知相关竞态测试。
- 覆盖首次失败后的额外重试次数、真实一秒间隔、重试耗尽、重试为零、任一地址族成功提前结束、等待期间取消、IPv4/IPv6 单栈恢复、Service 重启去重、下一次故障独立事件、SMTP 重试和恢复撤销。
- 覆盖未应用配置隔离、主动停止、无支持通道、探测中删除/停止、任务整体超时和四个并发上限。
- 覆盖旧数据库升级及鉴权、只读 API。
- 独立 agent review 发现单个 unit 查询异常影响整批检测的问题，已隔离并增加严格 Manager 回归测试，复查通过。
- 重试机制的独立复查发现新增参数被识别为所有任务的必填项，已修复 API 兼容性并覆盖备份任务更新和显式零次重试保存；双地址族成功立即返回、取消另一族的测试及 race 验证通过。

## 部署与回滚

目标为测试机 `10.2.78.11` 的管理服务。提交后构建 Linux amd64 binary；部署前停止管理服务并备份旧 binary 和一致性数据库，代理组件及订阅端保持运行。启动时自动迁移到 schema 12。

部署验证包含管理端和代理组件状态、订阅端健康、数据库版本、后台真实检测记录、任务参数及前端状态展示。故障与恢复通知通过本地模拟邮件验证，不通过修改真实上游制造故障。

回滚时先停止管理服务，再恢复本次部署前的 binary 及对应数据库备份，最后启动管理服务。不能仅降级 binary 后继续使用已升级数据库。

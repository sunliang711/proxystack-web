# 管理服务更新完成自动刷新

## 背景与实现

系统页面提交管理服务自更新后，前端原先只把任务交给任务中心追踪，服务重启期间没有明确的完成反馈，也不会自动刷新到新版本。

- 更新提交后显示分阶段动画，区分下载校验、服务重启、版本确认和完成刷新。
- 继续使用现有后台任务追踪；任务失败时停止版本检查并提示查看日志。
- 前端轮询 `/api/system/info`，只有实际运行版本与目标版本一致时才判定完成。
- 重启期间的连接失败视为正常等待，成功后延迟 800ms 自动刷新页面。
- 后台更新任务成功后开始自动确认，最长等待 5 分钟，超时后保留页面并提示手动检查。
- 离开页面时取消提交请求、版本检查和定时器，避免后台残留。
- 提交响应因网络异常丢失时保持操作锁定，并引导到任务中心确认，避免重复启动自更新。
- 开发模式不具备自动重启能力，页面禁用更新操作并给出说明。

## 数据与依赖

- 不新增后端接口、数据库迁移、配置项或环境变量。
- 不新增或升级依赖。

## 验证范围

- 目标版本带或不带 `v` 前缀均可匹配。
- 覆盖旧版本、重启断线、目标版本恢复、超时和取消。
- 前端类型检查、生产构建及桌面和窄屏浏览器布局。

# 预约升级已是最新版时延后一检查周期完成

## 问题背景

预约升级选择 `latest` 且管理服务当前已经是最新版本时，首次检查会立即将预约标记为成功，未按预约检查周期等待。

## 根因分析

预约 watcher 在检查前设置了下一次检查时间，但当前版本不低于发布版本的分支直接写入 `succeeded`，绕过了这次等待。

## 修复方案

- `latest` 首次确认当前已是最新版时，记录已解析版本并保持 `waiting`。
- 下一检查周期仍确认当前版本已是最新后，再标记 `succeeded`。
- 指定版本继续沿用原有逻辑，不增加等待。

## 文件与配置变更

- `internal/app/self_upgrade.go`：调整 `latest` 当前版本已满足时的状态流转。
- `internal/app/self_upgrade_test.go`：增加 `latest` 延后一周期完成和指定版本立即完成的回归测试。

## 验证结果

- `go test ./internal/app`
- `go test ./...`
- `go vet ./...`

## 风险与后续建议

预约状态仍持久化在现有 `self_upgrade_schedule` 设置中，不需要数据库迁移；服务重启后会继续按已记录的下一检查时间处理。

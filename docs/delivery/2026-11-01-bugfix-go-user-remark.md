# 用户管理备注导致订阅节点重名

## 问题与根因

用户 `xc` 设置管理备注 `xiaochen` 后，加入多个 Stack 的订阅入站时保存失败。`internal/configdoc/compile.go` 将用户备注复制到领域模型的 default 档案，随后用户引用展开和订阅生成将其作为节点名，优先于入站备注。同一用户的多个节点因此都叫 `xiaochen`，触发名称唯一性校验。

用户确认管理备注仅用于管理识别，节点应继续使用 `usa1 vmess`、`usa3 vmess` 等入站名称。

## 修复

- 配置编译时不再将用户的管理备注传入 default 档案的节点备注；数据库、导入导出及用户列表仍保存并显示原备注。
- 入站用户覆盖、非 default 凭据档案备注、入站节点备注及展示名模板继续生效。模板中的 `.remark` 不包含用户的管理备注。
- 更新用户创建、用户详情、入站用户覆盖和模板帮助，说明两类备注的用途。
- 新增配置校验及订阅生成回归测试，覆盖入站备注、自动名称、用户模板、入站模板、显式覆盖和具名档案；新增 HTTP 集成测试，覆盖带备注用户依次加入两个 Stack、保存和再次修改备注的流程。

## 订阅目录诊断

远端使用的新安装脚本将服务固定为 `sub --dir /opt/proxystack-web-sub serve`，但下载到的 Release 二进制仍默认使用 `/opt/proxystack-sub`。`main` 中的安装脚本不会编译 `main` 源码，而是下载 Release 二进制。此前导入操作已通过显式指定新目录恢复服务。

当前源码的 CLI 默认目录已是 `/opt/proxystack-web-sub`，本次没有修改安装脚本或默认目录；用户手册补充版本来源和显式目录的说明。

## 验证

- 修复前，六组配置回归用例均复现节点重名或用户模板名称被管理备注改变。
- 修复后，`go test ./...` 通过，包含完整的 HTTP 保存流程。
- 前端 `npm run build` 通过，包含 TypeScript 检查和 Vite 生产构建。
- `go run ./cmd/proxystack-web sub --help` 确认当前源码默认目录为 `/opt/proxystack-web-sub`。
- `git diff --check` 通过。

## 生效与兼容性

没有新增依赖、数据库迁移或订阅包格式变更。部署新二进制后，用户备注不再影响新保存配置的节点名；之前依赖管理备注生成的节点将恢复使用入站节点名。已有订阅包内容不会自动变化，需要按原流程应用配置、签发并导入新的订阅包。

本次完成本地修改与验证，未发布 Release 或部署远端。

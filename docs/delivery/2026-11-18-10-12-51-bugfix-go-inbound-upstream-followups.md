# 入站引用后续问题修复

日期：2026-11-18。

## 核实与修复

| 反馈 | 核实结果及修复 |
| --- | --- |
| 删除用户残留上游连接身份 | 确认遗漏。`RemoveUserRefs` 同步清空所有引用型上游中匹配该用户的 `User` 和 `Profile`，保留其他上游；真实 `DeleteUser` 服务事务回归覆盖 VMess 剩一个用户、Shadowsocks 剩零个用户。 |
| 无用户 VMess 引用缺少原因提示 | 确认表单缺少说明。显示明确警告，提示先为目标入站添加用户，继续阻止暂存无效引用。 |
| 目标列无法区分连接身份 | 确认缺少展示。目标链接下方显示所选用户／档案，空档案显示 default。 |
| 普通编辑隐式改写旧引用类型 | 确认有额外变更。用表单类型代理显示统一选项，普通修改名称或开关保留 `xray-socks5`；选择非 SOCKS5 入站时才升级为 `xray-inbound`。 |
| default 档案在快照和数据库间不一致 | 确认存在。Stack 规范化阶段将引用的 `profile: default` 归一为空，直接调用 `SaveDocument` 时也保持相同表示。回归比较保存返回值、原始修订 JSON 和数据库重新加载结果。 |

此前独立评审将用户删除失败视为刻意的引用保护，这一判断不成立。已在首次评审报告中追加更正，并更新原交付说明及用户指南。

## 行为边界

清空已删除用户的连接身份后沿用已有解析规则：目标入站仅剩一个用户时自动使用该用户，无用户的 Shadowsocks 使用入站自身密码。若目标 VMess 已无用户，或还有多个用户无法唯一选择，删除仍因配置无效而被拦截，事务不会保存部分修改，需要先调整目标入站或上游引用。

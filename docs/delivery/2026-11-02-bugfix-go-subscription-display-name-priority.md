# 订阅展示名优先级一致性修复

## 问题背景

普通节点按 Stack 已应用版本生成，直连节点按当前保存配置生成。用户清空用户级展示名模板后，普通节点仍可能使用已应用版本中的旧模板，而直连节点已经使用当前入站模板，导致同一用户的两类节点命名不一致。

## 根因分析

- 普通节点从已应用 revision 的完整配置快照生成，快照同时包含当时的用户、档案和展示名模板。
- 直连节点不依赖本机运行进程，直接使用当前保存配置。
- 展示名模板不改变 Xray/Mihomo 运行参数，因此只修改模板时可能没有待应用生成物，但普通节点仍保留旧快照中的命名字段。

## 修复方案

- 普通节点继续使用已应用版本的协议、端口和凭据，仅覆盖为当前保存配置中的展示名模板与节点备注。
- 普通节点和直连节点统一按以下顺序选择非空模板：入站用户覆盖、所选用户档案、Stack 入站、全局模板。
- 模板均为空时使用生效的节点备注；备注也为空时使用 `Stack 名称 + 协议`。
- 仅授权直连且不属于任何订阅入站的用户不再借用 Stack 中无关入站的模板。
- 在「系统设置 → 订阅」新增可选的全局展示名模板，默认留空，升级后不改变现有节点名。

## 文件与配置变更

- `internal/configdoc`：新增全局模板字段、命名字段覆盖和直连命名规则。
- `internal/generator/sub`：统一用户、入站、全局模板的选择顺序。
- `internal/app/subscription.go`：已应用节点生成前覆盖当前命名字段。
- `web/src/views/SettingsView.vue`：新增全局展示名模板输入项。
- `web/src/components/TemplateInput.vue`：更新完整优先级说明。

## 验证结果

- 覆盖用户模板清空后无需重新应用，普通节点和直连节点同时使用当前入站模板。
- 覆盖入站模板清空后，两类节点同时使用当前全局模板。
- 覆盖仅直连用户不借用无关入站模板。
- 覆盖全局模板语法与节点名唯一性校验。
- 后端 `go test ./...` 通过。
- 前端 `vue-tsc --noEmit` 通过。
- 前端 `pnpm run build` 通过。

## 风险与兼容性

- 全局模板默认空，不改变已有配置的命名结果。
- 未应用的协议、端口、凭据和用户档案选择不会提前进入普通节点订阅。
- 当前命名规则可能在保存后立即改变订阅包内容，仍需重新发布订阅包并导入订阅端后才会影响外部订阅。
- 当前命名字段无法在已应用拓扑中安全渲染时，普通节点回退到该 revision 已应用时的命名字段；直连节点仍按当前配置命名，订阅构建会记录 warning 提示该降级。

## 独立评审与修复

独立 Agent 评审发现一个阻断问题：当前配置拓扑与已应用 revision 的拓扑可能不同。若当前配置已关闭或移除一个订阅入站，`{{ .stack }}` 等模板在当前拓扑中可以通过节点名唯一性校验，但覆盖到仍包含多个入站的已应用快照后会产生重名。覆盖后的订阅输入渲染失败时，原实现会跳过整个 revision，导致该 revision 下全部普通节点消失。

主 Agent 增加 revision 级降级保护：先使用当前命名字段渲染已应用拓扑；失败时保留当前 `ExternalHost`，改用该 revision 已应用时的命名字段重试；仅两次渲染都失败时才跳过 revision。回退成功会记录包含覆盖失败原因的 warning，便于定位配置冲突。

新增回归测试覆盖：已应用版本包含两个订阅入站，当前配置关闭其中一个入站后设置 `{{ .stack }}`，当前配置仍可保存，订阅预览继续保留两个已应用节点且使用已应用名称。修复后的定向测试通过，独立 Agent 复审未发现新的阻断或警告问题。

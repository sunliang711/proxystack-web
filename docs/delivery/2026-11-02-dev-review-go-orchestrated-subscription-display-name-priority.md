# 订阅展示名模板优先级开发与独立评审交付

交付日期：2026-11-02。主 Agent 完成实现、测试和评审问题修复，独立 Agent 执行首次评审与修复后复审，文档 Agent 整理交付记录。

## 任务背景

Stack 入站配置展示名模板为 `{{ .stack | toUpper }} {{ .user }}` 时，允许直连的用户订阅中，直连节点使用完整模板，普通节点却可能只使用用户详情中的旧模板。目标是统一普通节点和直连节点的命名优先级，并增加全局模板作为最低模板兜底。

## 最终方案

- 正常命名优先级统一为：入站用户覆盖、所选用户档案/default 用户模板、Stack 入站模板、全局模板、生效备注、`Stack 名称 + 协议`。
- 普通节点继续使用已应用 revision 的协议、端口和凭据，仅即时覆盖当前保存的命名字段。
- 当前命名字段在已应用拓扑中编译或渲染失败时，保留当前 `ExternalHost`，回退到该 revision 已应用时的命名字段，并记录 warning；两次都失败才跳过 revision。
- 直连节点始终使用当前配置；仅授权直连且不属于任何订阅入站的用户不会借用无关入站模板。
- 「系统设置 → 订阅」增加可选的全局展示名模板，页面和帮助文本标注完整优先级。
- 全局模板参与语法校验和最终节点名唯一性校验。

## 独立评审与处理

首次评审发现一个阻断问题：只按当前拓扑校验的模板可能在已应用拓扑中产生重名，导致订阅构建跳过整个 revision。主 Agent 增加已应用命名回退和 warning，并补充对应回归测试。

独立 Agent 对修复进行复审，确认只有当前命名和已应用命名两次渲染都失败时才跳过 revision，未发现新的阻断或警告问题，复审通过。

## 风险结论

正常场景下普通节点和直连节点使用同一优先级。发生命名覆盖降级时，普通节点暂时沿用已应用名称，直连节点可能已使用当前名称；该取舍避免整组节点消失，并有 warning 可追踪。未引入数据库迁移、新依赖或部署配置，未记录任何环境凭据。

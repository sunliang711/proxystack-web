# Stack 上游直连订阅

## 背景与范围

允许管理员在 Stack 的「上游」中指定直连用户。原入站订阅节点保留，授权用户额外获得外部上游节点，直接连接上游，不经过本机代理进程。

## 行为与配置

- Stack 新增可省略的 `direct_users` 用户名列表，默认空，不隐式授权旧用户。
- 直连授权独立于入站用户列表，不要求本机 Xray/Mihomo 启用或已经应用配置。
- 仅处理 `type: raw` 的外部上游；不处理 `xray-socks5` 引用和代理组，不依赖运行时代理组选择。
- 每个授权用户、每个外部上游生成一个节点。单上游名称追加 `[DRT]`，多上游追加 ` · 上游名[DRT]`。
- 基础名称优先沿用该用户第一个进入订阅的入站及其档案/模板覆盖；用户不属于入站时使用首个订阅入站；无订阅入站时使用 Stack 与上游协议。地区沿用所选入站。
- 原生认证、TLS、传输参数按现有 direct 节点链路传递；移除服务器专用的 `dialer-proxy`、`interface-name`、`routing-mark`，避免客户端沿用本机拨号链或网卡设置。
- Stack 停用或用户逐 Stack 暂停时移除直连节点；用户停用/到期沿用现有发布与订阅端规则。
- 保存后管理端即可预览，发布订阅包并由订阅端导入后对外生效，无需应用运行配置。撤销后需重新发布。
- 上游凭据会下发给授权用户。已下载的配置无法仅靠撤销订阅授权失效，需在上游更换凭据。直连流量无法纳入本机统计，也无法由本机配额限制阻断。

## 实现与兼容

- 数据库迁移 `00009_stack_direct_users.sql` 新增 Stack/用户关联表；保存和引用调整在现有事务内完成。
- 用户改名、删除、引用导出同步维护授权，导入导出沿用现有文档格式。
- 订阅快照复用原生 direct 节点和签名包，不增加外部依赖或改变订阅 URL。
- HTTP/SOCKS 上游转换为 Surge 时保留原生用户名密码及 TLS/SNI；不支持的协议沿用过滤机制，带插件或非 AEAD VMess 的上游不生成不可用的 Surge 节点。
- 配置模板以局部 `autoescape off` 文本块渲染，防止引号、`&`、`<`、`>` 被转成 HTML 实体，兼容内置和自定义模板。
- 前端 OpenAPI 与 TypeScript 定义已更新；上游页提供多选、全选和清空入口。

## 验证

- `go test ./...`。
- 前端 `npm --prefix web run build`（包含类型检查）。
- 从第 8 版数据库迁移，旧 Stack 保留配置且无默认授权。
- 真实签名包发布与独立订阅端导入：Clash、Premium Clash、Surge；原节点保留、多个上游、仅直连用户、暂停、停用、到期、撤销和用户隔离。
- 原生参数不丢失、生成过程不改写原始上游、节点重名校验、授权引用生命周期和特殊字符凭据回归测试。
- 独立 agent review，发现的 Surge HTML 转义及必要扩展丢失问题已修复并加入回归测试。

## 发布与回滚

测试部署目标为 `10.2.78.11`，同步更新管理端及订阅端 binary；管理端首次启动自动执行迁移。发布前备份两份 binary 与管理端数据库。

回滚时先停止管理服务，再恢复旧 binary 和对应 SQLite 备份，避免旧程序面对新迁移记录；订阅端同步恢复原 binary。任何临时验证授权均在测试结束后清除，不保留临时节点。

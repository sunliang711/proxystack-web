# 订阅端完整配置重复查看交付

## 任务背景

创建订阅端目标后，完整配置窗口原本只在创建或轮换时显示。管理员关闭窗口后无法再次取得当前发布 Secret，只能通过轮换 Secret 重新配置订阅端。

## 实现方案

- 在订阅端目标操作列增加「完整配置」按钮，保留原有不含 Secret 的「配置说明」。
- 新增受登录保护的完整配置查询接口，返回当前发布 Secret、受限 `authorized_keys`、`sshd_config`、Secret 导入命令和目标信息。
- 普通目标列表继续只返回 Secret 掩码，不扩大默认接口的敏感信息暴露面。
- 完整配置响应设置 `Cache-Control: no-store`，每次查看记录明文凭据审计日志，日志不包含 Secret。
- 窗口关闭后前端清除本次响应；再次点击按钮时重新向后端读取当前配置。

## 接口变更

- 新增 `GET /api/sub-publish/targets/{id}/setup`。
- 接口沿用管理端登录鉴权，目标不存在时返回统一的未找到错误。
- 无数据库结构、配置项或第三方依赖变更。

## 测试范围

- Service 测试覆盖同一目标的完整配置重复读取。
- API 测试覆盖列表脱敏、重复查看、`no-store` 以及轮换后返回新 Secret。
- 前端专项测试覆盖操作列入口、敏感信息提示和重复查看说明。

## 风险说明

完整配置接口会返回明文 Secret，因此仅由管理员登录态访问，并通过禁止缓存和审计降低误暴露风险。数据库中原本就保存投递所需的 Secret 明文，本次不改变其存储方式。

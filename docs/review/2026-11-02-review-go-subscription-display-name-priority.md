## 评审基线

- 检查命名优先级在普通节点、直连节点、配置校验和生成器之间是否一致。
- 检查普通节点是否继续使用已应用 revision 的协议、端口和凭据，避免未应用运行配置提前进入订阅。
- 检查当前配置与已应用拓扑不一致、仅直连用户、旧配置兼容、节点名唯一性和错误降级路径。
- 检查硬编码凭据、日志泄密、并发、资源释放和必要测试覆盖。

## 首次评审发现

严重等级：阻断。

当前命名字段直接覆盖到已应用 revision，但保存配置时的模板与节点名唯一性校验只针对当前拓扑。当前配置关闭或移除一个订阅入站后，模板可能在当前拓扑中合法，却在仍包含多个入站的已应用拓扑中产生重名。覆盖后的订阅输入渲染失败会跳过整个 revision，使该 revision 下全部普通节点消失。

典型触发条件：

1. 已应用 revision 中，同一用户属于两个订阅入站。
2. 当前配置关闭其中一个入站的订阅或移除该用户，但尚未 Apply。
3. 用户或全局模板设置为 `{{ .stack }}`，当前拓扑中仅剩一个节点，因此保存校验通过。
4. 构建订阅时模板覆盖到已应用拓扑，两个节点重名，整个 revision 被跳过。

## 修复与验证

主 Agent 在覆盖当前命名字段前保留已应用快照。构建每个 revision 时先尝试当前命名字段；失败后保留当前 `ExternalHost`，使用已应用命名字段重试。只有当前命名和已应用命名两次渲染都失败时才跳过 revision，回退成功会记录 warning。

新增回归测试覆盖当前拓扑与已应用拓扑不一致的触发路径，并验证两个已应用节点均保留原名称。修复后的定向 Go 测试与 `go test ./...` 全量测试均通过，前端类型检查和生产构建也再次通过。

## 复审结论

## 残余风险

发生降级时，普通节点暂时使用已应用名称，直连节点仍可能使用当前名称。这是为了避免整组普通节点消失的保护行为，并通过 warning 暴露冲突；待相关 Stack Apply 后，两类节点会重新按一致的当前拓扑计算名称。
